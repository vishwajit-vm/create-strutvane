# .strutvane

Managed by Strutvane. Do not edit files here by hand.

Committed (shared by the team, needed by `sv upgrade` to merge template changes):

- `lock.json`: which files were ejected, from which template version, with their hashes
- `base/`: the original template output of each ejected file (the merge base)
- `templates/`: generator templates you ejected to customise (`sv eject templates`)

Git-ignored (local, rebuilt on `dev` / `build`):

- `registry.gen.ts` and other `*.gen.ts` files: generated registry and types
- `staging/`: the temporary area for safe, all-or-nothing file changes

# CLAUDE.md: northwind

Project memory for AI assistants. Keep it short and current.

## What this is

A full-stack Strutvane app: REST API, database and a generated React UI built on Strutvane (TypeScript, ESM, Node 24+).
Preset: `full`, database: `postgres`, auth: `email`, multi-tenant.

## Rules

- Models in `app/models/` are the source of truth. Change a model, then run `npm run sv -- migrate`; never hand-edit applied migrations.
- Generate code with `npm run sv -- make:*` (model, policy, job, …) instead of writing boilerplate.
- Read settings through `config/*.ts`, never `process.env`. A new env key goes into `env.schema.ts`, `.env.example` and `.env`.
- Never commit `.env`, secrets, `storage/` or generated `.strutvane/` files (only its `lock.json`, `base/` and `templates/` are committed). `docker/` is local-only and git-ignored.
- Log with the app logger, never `console.*`. Never log secrets or request bodies.
- Authorization is deny-by-default: add a policy for every new model.
- Roles: `admin`, `member`, `viewer`, `owner` (a tenant's creator, inside that tenant). The role map in `config/auth.ts` grants on top of the policies; a policy `deny` always wins.
- The UI is `<StrutvaneApp>` from @strutvane/ui, built from the API manifest. Add screens as routes in `web/router.tsx` and customise widgets, cells and messages with `overrides` in `web/app.tsx`; never copy the built-in pages.

## Before you finish a change

```bash
npm run lint
npm run typecheck
npm run test
```

# northwind

This is a full-stack Strutvane app: REST API, database and a generated React UI, created with [create-strutvane](https://github.com/vishwajit-vm/create-strutvane).

## Quick start

You need Node.js 24 or newer and Docker (for the local database and services).

```bash
npm install
npm run services:up     # starts the local database and services (Docker)
npm run sv -- migrate
npm run sv -- db:seed
npm run dev
```

The API runs on http://localhost:3000 (interactive API docs at http://localhost:3000/docs).

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Start the API (and UI) with hot reload |
| `npm run build` | Production build |
| `npm run start` | Run the production build |
| `npm run test` | Unit and feature tests (Vitest) |
| `npm run test:e2e` | Browser tests (Playwright) |
| `npm run lint` | Lint and format check (Biome) |

| `npm run sv -- make:model Invoice` | Add a model: migration, CRUD API, permissions, tests and UI pages |
| `npm run sv -- migrate` | Generate and apply migrations from your models |
| `npm run sv -- routes` | List every API route |
| `npm run sv -- env:check` | Compare .env with .env.example |
| `npm run sv -- help` | Every command of this project (built in and from installed packages) |

`npm run sv -- <command>` runs the Strutvane CLI pinned in this project (`@strutvane/cli` in
devDependencies), so its help lists your own and your packages' commands. A global `strutvane`
command runs the same CLI for everything except `help`, which describes the launcher itself.

## Project layout

- `app/`: your code (models, policies, services, routes, jobs, providers)
- `database/`: migrations (generated, committed), seeders and factories
- `config/`: typed settings that read the validated environment
- `web/`: the UI (pages are generated; override only what you customise)
- `tests/`: unit, feature and browser (e2e) tests
- `env.ts` / `env.schema.ts`: every environment variable, validated at startup
- `strutvane.config.ts`: which Strutvane packages are active
- `docker/`: local services only, **git-ignored** (never deployed)
- `.strutvane/`: generated files (registry, types, staging), git-ignored, except the upgrade state `lock.json`, `base/` and `templates/`, which are committed so `sv upgrade` works for the whole team
- `storage/`: runtime files (logs, uploads), git-ignored

===== app/models/README.md =====
# Models

A model is the single source of truth for one kind of record: its fields and their types.
From it, Strutvane generates the migration, the CRUD API, validation, permissions and UI pages.

Create one with `npm run sv -- make:model Invoice number:string:unique amount:decimal(12,2)`, then run `npm run sv -- migrate`.

Users are not a model here: accounts, sessions, roles and memberships belong to @strutvane/auth.
A request knows its user as the actor (`actor.id`). For profile fields, add a model keyed by
that id: `npm run sv -- make:model Profile userId:string:unique jobTitle:string`.

Create one with `npm run sv -- make:policy Invoice`.

===== config/auth.ts =====
/**
 * Authentication and authorization (@strutvane/auth).
 * Values come from the validated environment (env.ts); defaults live in .env.example.
 */
import { defineAuthConfig } from '@strutvane/auth'
import { env } from '../env.ts'

export default defineAuthConfig({
  methods: ['email'],
  secret: env.AUTH_SECRET,
  session: { driver: env.AUTH_SESSION_DRIVER, idleMinutes: env.AUTH_SESSION_LIFETIME },
  tokens: { accessTokenSeconds: env.AUTH_JWT_TTL },
  registration: env.AUTH_ALLOW_REGISTRATION,
  mfa: env.AUTH_MFA,
  /**
   * Roles (enforced by @strutvane/auth together with app/policies/*.policy.ts: a policy
   * `deny` always wins). Every model gets permissions like `invoice.viewAny`, `invoice.create`,
   * …; `*` patterns match every model. `own: true` limits a permission to records whose
   * `ownerId` is the signed-in user; a model without an `ownerId` field never matches it.
   * `scope: 'global'` counts only outside tenants (platform administrators, like the seed admin),
   * `scope: 'tenant'` only inside the user's active tenant, where `*` patterns reach only
   * tenant-scoped models. Policies use the same role names.
   */
  roles: {
    admin: {
      permissions: [
        '*',
        { action: 'user.viewAny', scope: 'global' },
        { action: 'user.view', scope: 'global' },
        { action: 'user.update', scope: 'global' },
        { action: 'user.delete', scope: 'global' },
      ],
    },
    member: {
      permissions: [
        '*.viewAny',
        '*.view',
        '*.create',
        { action: '*.update', own: true },
        { action: '*.delete', own: true },
      ],
    },
    viewer: { permissions: ['*.viewAny', '*.view'] },
    owner: { scope: 'tenant', permissions: ['*'] },
  },
  /**
   * Identity, authorization, tenancy and audit records: no wildcard (not even admin `*`) ever
   * matches them. Grant access by exact name, e.g. `user.view`.
   */
  wildcardExclude: [
    // Identity
    'user',
    'account',
    'session',
    'verification',
    'mfaFactor',
    'passkey',
    'impersonationSession',
    // Machine access
    'apiToken',
    'serviceAccount',
    'oauthClient',
    'ssoConnection',
    'scimToken',
    // Authorization
    'role',
    'rolePermission',
    'roleInherit',
    'assignment',
    'permission',
    // Tenancy
    'tenant',
    'tenantDomain',
    'membership',
    'invitation',
    'team',
    'teamMember',
    // Audit
    'auditEvent',
  ],
  /** What a new model gets: the role patterns above, or `admin-only` for stricter orgs. */
  newModelDefaults: 'inherit-role-patterns' as const,
  /** Roles a self-registered user gets (none: an admin grants them). */
  defaultRoles: [] as string[],
  seedAdmin: { email: env.SEED_ADMIN_EMAIL, password: env.SEED_ADMIN_PASSWORD, role: 'admin' },
  /**
   * Origins allowed to call the sign-in, sign-up and other state-changing auth endpoints.
   * Add the origin of a UI served from another domain.
   */
  trustedOrigins: [env.APP_URL],
  /**
   * Proxy addresses or CIDRs whose X-Forwarded-For auth may use for rate limiting. Leave empty
   * in a Strutvane app: TRUST_PROXY (config/app.ts) already resolves the client address.
   */
  trustedProxies: [] as string[],
})

===== database/factories/README.md =====
# Factories

Fake-data builders for tests and seeders. `npm run sv -- make:model Invoice` generates one per model:

```ts
import { defineFactory } from '@strutvane/framework/testing'
import Invoice from '../../app/models/invoice.model.ts'

export default defineFactory(Invoice, ({ fake, related }) => ({
  number: fake.words(2),
  customer: related('Customer'),
}))
```

- `related('Customer')` reuses an existing Customer when there is one and creates one otherwise.
- In a seeder: `await create(InvoiceFactory, 20)`. In a test: `await InvoiceFactory.createMany(t, 3)`.
- `npm run sv -- make:model` registers each model's seeder in `database/seeders/database.seeder.ts`, parents before children, so related records exist before the records that point to them.

===== database/migrations/README.md =====
# Migrations

Generated by `npm run sv -- migrate` from your models: plain SQL, reviewed and committed.

- Never edit a migration that has already been applied: create a new one instead.
- Sign-in tables (accounts, sessions, tenants, memberships) ship with @strutvane/auth: `npm run sv -- migrate` applies them together with these files.
- Renames are always asked, never guessed. Destructive changes need confirmation.

===== env.schema.ts =====
/**
 * The shape of this app's environment, validated once at startup by `env.ts`.
 *
 * Generated by create-strutvane together with `.env.example`. When you add a variable, add it
 * here AND to `.env.example` (`sv env:check` reports any difference).
 */
import { z } from 'zod'

/** An empty value in .env means "not set". */
const optional = <T extends z.ZodType>(schema: T) =>
  z.preprocess((value) => (value === '' ? undefined : value), schema.optional())

/** "true" / "false" strings → booleans. Anything else is an error, never silently false. */
const bool = z.enum(['true', 'false']).transform((value) => value === 'true')

/** Comma-separated values → a trimmed list. */
const list = z
  .string()
  .min(1)
  .transform((value) =>
    value
      .split(',')
      .map((item) => item.trim())
      .filter(Boolean),
  )

export const envSchema = z
  .object({
    // Application
    APP_NAME: z.string().min(1),
    APP_ENV: z.enum(['local', 'test', 'staging', 'production']),
    APP_KEY: z.string().min(32, 'must be a long random secret (32+ characters)'),
    APP_URL: z.url(),
    APP_PORT: z.coerce.number().int().min(1).max(65535),
    TRUST_PROXY: z.coerce.number().int().min(0),
    APP_DEBUG: bool,
    APP_TIMEZONE: z.string().min(1),
    APP_LOCALE: z.string().min(1),
    // Logging & Observability
    LOG_LEVEL: z.enum(['trace', 'debug', 'info', 'warn', 'error', 'fatal']),
    LOG_FORMAT: z.enum(['pretty', 'json']),
    LOGS_ENABLED: bool,
    LOGS_DRIVER: z.enum(['file', 'database', 'stdout']),
    LOGS_PATH: z.string().min(1),
    LOGS_RETENTION_DAYS: z.coerce.number().int().min(0),
    LOGS_MAX_DAILY_SIZE: z.string().regex(/^\d+(KB|MB|GB)$/i, 'use a size like 30MB'),
    LOGS_REQUEST_BODIES: bool,
    LOGS_VIEWER: bool,
    LOGS_VIEWER_PATH: z.string().min(1),
    LOGS_VIEWER_TOKEN: optional(z.string().min(1)),
    // Database
    DB_CONNECTION: z.enum(['postgres', 'mysql', 'sqlite', 'azure-postgres', 'azure-mysql']),
    DB_HOST: z.string().min(1),
    DB_PORT: z.coerce.number().int().min(1).max(65535),
    DB_DATABASE: z.string().min(1),
    DB_USERNAME: z.string().min(1),
    DB_PASSWORD: z.string().min(32, 'must be a long random secret (32+ characters)'),
    DB_SSL: bool,
    DB_POOL_MIN: z.coerce.number().int().min(0),
    DB_POOL_MAX: z.coerce.number().int().min(0),
    // Cache / Queue
    CACHE_DRIVER: z.enum(['memory', 'valkey', 'database']),
    VALKEY_URL: z.url(),
    // Auth
    AUTH_SECRET: z.string().min(32, 'must be a long random secret (32+ characters)'),
    AUTH_SESSION_DRIVER: z.enum(['database', 'memory']),
    AUTH_SESSION_LIFETIME: z.coerce.number().int().min(0),
    AUTH_JWT_TTL: z.coerce.number().int().min(0),
    AUTH_ALLOW_REGISTRATION: bool,
    AUTH_MFA: z.enum(['off', 'optional', 'required']),
    SEED_ADMIN_EMAIL: z.email(),
    SEED_ADMIN_PASSWORD: z.string().min(32, 'must be a long random secret (32+ characters)'),
    // Tenancy
    TENANCY_ENABLED: bool,
    TENANCY_STRATEGY: z.enum(['shared', 'schema', 'database']),
    TENANCY_RESOLVE: list,
    // HTTP / API
    API_PREFIX: z.string().min(1),
    API_VERSION: z.string().min(1),
    API_DOCS: bool,
    CORS_ORIGINS: list,
    RATE_LIMIT: z.string().regex(/^\d+\/(s|min|h|day)$/, 'use a rate like 120/min'),
    // UI
    VITE_APP_NAME: z.string().min(1),
    VITE_API_URL: z.string().min(1),
  })
  .superRefine((env, ctx) => {
    if (env.APP_ENV !== 'local' && env.APP_DEBUG) {
      ctx.addIssue({
        code: 'custom',
        path: ['APP_DEBUG'],
        message: 'APP_DEBUG may only be true when APP_ENV=local (it would expose error details)',
      })
    }
    // config/cors.ts allows credentials (cookies), so a wildcard origin is never safe.
    if (env.CORS_ORIGINS.some((origin) => origin.includes('*'))) {
      ctx.addIssue({
        code: 'custom',
        path: ['CORS_ORIGINS'],
        message: 'CORS_ORIGINS cannot contain * while credentials are allowed: list each origin',
      })
    }
    const insecure = env.CORS_ORIGINS.some((origin) => !origin.startsWith('https://'))
    if (env.APP_ENV === 'production' && insecure) {
      ctx.addIssue({
        code: 'custom',
        path: ['CORS_ORIGINS'],
        message: 'every CORS_ORIGINS entry must start with https:// in production',
      })
    }
  })

/** The validated environment type. */
export type Env = z.infer<typeof envSchema>
