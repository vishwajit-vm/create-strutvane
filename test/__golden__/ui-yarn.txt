===== .strutvane/README.md =====
# .strutvane

Managed by Strutvane. Do not edit files here by hand.

Committed (shared by the team, needed by `sv upgrade` to merge template changes):

- `lock.json`: which files were ejected, from which template version, with their hashes
- `base/`: the original template output of each ejected file (the merge base)
- `templates/`: generator templates you ejected to customise (`sv eject templates`)

Git-ignored (local, rebuilt on `dev` / `build`):

- `registry.gen.ts` and other `*.gen.ts` files: generated registry and types
- `staging/`: the temporary area for safe, all-or-nothing file changes

===== README.md =====
# acme-portal

This is a Strutvane UI for an existing API (screens generated from its manifest or OpenAPI document), created with [create-strutvane](https://github.com/vishwajit-vm/create-strutvane).

## Quick start

You need Node.js 24 or newer.

```bash
yarn install
yarn dev
```

The UI runs on http://localhost:5173 and talks to the API set in `VITE_API_URL`.

## Commands

| Command | What it does |
|---|---|
| `yarn dev` | Start the UI with hot reload |
| `yarn build` | Production build |
| `yarn start` | Preview the production build |
| `yarn test` | Unit and feature tests (Vitest) |
| `yarn test:e2e` | Browser tests (Playwright) |
| `yarn lint` | Lint and format check (Biome) |
| `yarn typecheck` | TypeScript check |
| `yarn sv env:check` | Compare .env with .env.example |

## Project layout

- `config/`: typed settings that read the validated environment
- `web/`: the UI (pages are generated; override only what you customise)
- `tests/`: unit, feature and browser (e2e) tests
- `env.ts` / `env.schema.ts`: every environment variable, validated at startup
- `strutvane.config.ts`: which Strutvane packages are active
- `.strutvane/`: generated files (registry, types, staging), git-ignored, except the upgrade state `lock.json`, `base/` and `templates/`, which are committed so `sv upgrade` works for the whole team

## Environment variables

`.env` holds your local values and secrets and is **never committed**. `.env.example` lists every key
with documentation and is committed. The app checks every key at startup and stops with one clear
message if something is missing or invalid.

| Key | Default | What it does |
|---|---|---|
| **Application** | | |
| `APP_NAME` | `acme-portal` | Shown in the UI, emails and logs |
| `APP_ENV` | `local` | Where this copy of the app runs (local \| test \| staging \| production) |
| `APP_URL` | `http://localhost:5173` | Public URL of this app |
| `APP_PORT` | `5173` | Port the dev server listens on |
| **UI** | | |
| `VITE_APP_NAME` | `acme-portal` | App name shown in the browser (VITE_ keys are public) |
| `VITE_API_URL` | `http://localhost:3000/api/v1` | API base URL used by the UI |
| `API_OPENAPI_URL` | `http://localhost:3000/openapi.json` | OpenAPI document of the API this UI connects to |

## Secrets

- Secrets were generated for you in `.env` when the project was created.
- In staging and production, set them through your hosting platform or secret store, never in files.

===== env.schema.ts =====
/**
 * The shape of this app's environment, validated once at startup by `env.ts`.
 *
 * Generated by create-strutvane together with `.env.example`. When you add a variable, add it
 * here AND to `.env.example` (`sv env:check` reports any difference).
 */
import { z } from 'zod'

export const envSchema = z.object({
  // Application
  APP_NAME: z.string().min(1),
  APP_ENV: z.enum(['local', 'test', 'staging', 'production']),
  APP_URL: z.url(),
  APP_PORT: z.coerce.number().int().min(1).max(65535),
  // UI
  VITE_APP_NAME: z.string().min(1),
  VITE_API_URL: z.string().min(1),
  API_OPENAPI_URL: z.url(),
})

/** The validated environment type. */
export type Env = z.infer<typeof envSchema>

===== tests/unit/env.test.ts =====
/**
 * Guards the environment contract: a complete .env is accepted and a broken one is refused.
 * Keep it passing when you add variables (add them to `valid` below).
 */
import { describe, expect, test } from 'vitest'
import { envSchema } from '../../env.schema.ts'

const valid = {
  APP_NAME: 'acme-portal',
  APP_ENV: 'local',
  APP_URL: 'http://localhost:5173',
  APP_PORT: '5173',
  VITE_APP_NAME: 'acme-portal',
  VITE_API_URL: 'http://localhost:3000/api/v1',
  API_OPENAPI_URL: 'http://localhost:3000/openapi.json',
}

describe('environment', () => {
  test('accepts a complete environment', () => {
    expect(envSchema.safeParse(valid).success).toBe(true)
  })

  test('refuses a missing required key', () => {
    const { APP_NAME: _removed, ...incomplete } = valid
    expect(envSchema.safeParse(incomplete).success).toBe(false)
  })
})

===== web/app.tsx =====
/**
 * The app shell. <StrutvaneProvider> loads the API manifest, so every resource gets its list,
 * form and detail pages without code. Override single pages in web/pages/<resource>/.
 */
import { StrutvaneProvider } from '@strutvane/ui/react'
import { routes } from './router.tsx'

export function App() {
  return (
    <StrutvaneProvider apiUrl={import.meta.env.VITE_API_URL} routes={routes}>
      <main className="sv-shell">
        <h1>{import.meta.env.VITE_APP_NAME}</h1>
        <p>Connected to your API. Resources from its manifest appear in the menu.</p>
      </main>
    </StrutvaneProvider>
  )
}
