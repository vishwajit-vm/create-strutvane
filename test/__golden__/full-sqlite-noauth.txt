# .strutvane

Managed by Strutvane. Do not edit files here by hand.

Committed (shared by the team, needed by `sv upgrade` to merge template changes):

- `lock.json`: which files were ejected, from which template version, with their hashes
- `base/`: the original template output of each ejected file (the merge base)
- `templates/`: generator templates you ejected to customise (`sv eject templates`)

Git-ignored (local, rebuilt on `dev` / `build`):

- `registry.gen.ts` and other `*.gen.ts` files: generated registry and types
- `staging/`: the temporary area for safe, all-or-nothing file changes

# CLAUDE.md: kiosk

Project memory for AI assistants. Keep it short and current.

## What this is

A full-stack Strutvane app: REST API, database and a generated React UI built on Strutvane (TypeScript, ESM, Node 24+).
Preset: `full`, database: `sqlite`.

## Rules

- Models in `app/models/` are the source of truth. Change a model, then run `pnpm sv migrate`; never hand-edit applied migrations.
- Generate code with `pnpm sv make:*` (model, policy, job, …) instead of writing boilerplate.
- Read settings through `config/*.ts`, never `process.env`. A new env key goes into `env.schema.ts`, `.env.example` and `.env`.
- Never commit `.env`, secrets, `storage/` or generated `.strutvane/` files (only its `lock.json`, `base/` and `templates/` are committed).
- Log with the app logger, never `console.*`. Never log secrets or request bodies.
- Authorization is deny-by-default: add a policy for every new model.
- The UI is `<StrutvaneApp>` from @strutvane/ui, built from the API manifest. Add screens as routes in `web/router.tsx` and customise widgets, cells and messages with `overrides` in `web/app.tsx`; never copy the built-in pages.

## Before you finish a change

```bash
pnpm lint
pnpm typecheck
pnpm test
```

# kiosk

This is a full-stack Strutvane app: REST API, database and a generated React UI, created with [create-strutvane](https://github.com/vishwajit-vm/create-strutvane).

## Quick start

You need Node.js 24 or newer.

```bash
pnpm install
pnpm sv migrate
pnpm sv db:seed
pnpm dev
```

`pnpm` not installed? Run the same commands through Corepack: `corepack pnpm@12.18.0 <command>`.

The API runs on http://localhost:3000 (interactive API docs at http://localhost:3000/docs).

## Commands

| Command | What it does |
|---|---|
| `pnpm dev` | Start the API (and UI) with hot reload |
| `pnpm build` | Production build |
| `pnpm start` | Run the production build |
| `pnpm test` | Unit and feature tests (Vitest) |
| `pnpm test:e2e` | Browser tests (Playwright) |
| `pnpm lint` | Lint and format check (Biome) |
| `pnpm typecheck` | TypeScript check |
| `pnpm sv make:model Invoice` | Add a model: migration, CRUD API, permissions, tests and UI pages |
| `pnpm sv migrate` | Generate and apply migrations from your models |
| `pnpm sv routes` | List every API route |
| `pnpm sv env:check` | Compare .env with .env.example |
| `pnpm sv help` | Every command of this project (built in and from installed packages) |

`pnpm sv <command>` runs the Strutvane CLI pinned in this project (`@strutvane/cli` in
devDependencies), so its help lists your own and your packages' commands. A global `strutvane`
command runs the same CLI for everything except `help`, which describes the launcher itself.

## Project layout

- `app/`: your code (models, policies, services, routes, jobs, providers)
- `database/`: migrations (generated, committed), seeders and factories
- `config/`: typed settings that read the validated environment
- `web/`: the UI (pages are generated; override only what you customise)
- `tests/`: unit, feature and browser (e2e) tests
- `env.ts` / `env.schema.ts`: every environment variable, validated at startup
- `strutvane.config.ts`: which Strutvane packages are active
- `pnpm-workspace.yaml`: pnpm settings: lets esbuild run its install step (pnpm blocks dependency build scripts by default) and exempts Strutvane pre-releases from the minimum release age
- `.strutvane/`: generated files (registry, types, staging), git-ignored, except the upgrade state `lock.json`, `base/` and `templates/`, which are committed so `sv upgrade` works for the whole team
- `storage/`: runtime files (logs, uploads), git-ignored

===== database/factories/README.md =====
# Factories

Fake-data builders for tests and seeders. `pnpm sv make:model Invoice` generates one per model:

```ts
import { defineFactory } from '@strutvane/framework/testing'
import Invoice from '../../app/models/invoice.model.ts'

export default defineFactory(Invoice, ({ fake, related }) => ({
  number: fake.words(2),
  customer: related('Customer'),
}))
```

- `related('Customer')` reuses an existing Customer when there is one and creates one otherwise.
- In a seeder: `await create(InvoiceFactory, 20)`. In a test: `await InvoiceFactory.createMany(t, 3)`.
- `pnpm sv make:model` registers each model's seeder in `database/seeders/database.seeder.ts`, parents before children, so related records exist before the records that point to them.

===== env.schema.ts =====
/**
 * The shape of this app's environment, validated once at startup by `env.ts`.
 *
 * Generated by create-strutvane together with `.env.example`. When you add a variable, add it
 * here AND to `.env.example` (`sv env:check` reports any difference).
 */
import { z } from 'zod'

/** "true" / "false" strings → booleans. Anything else is an error, never silently false. */
const bool = z.enum(['true', 'false']).transform((value) => value === 'true')

/** Comma-separated values → a trimmed list. */
const list = z
  .string()
  .min(1)
  .transform((value) =>
    value
      .split(',')
      .map((item) => item.trim())
      .filter(Boolean),
  )

export const envSchema = z
  .object({
    // Application
    APP_NAME: z.string().min(1),
    APP_ENV: z.enum(['local', 'test', 'staging', 'production']),
    APP_KEY: z.string().min(32, 'must be a long random secret (32+ characters)'),
    APP_URL: z.url(),
    APP_PORT: z.coerce.number().int().min(1).max(65535),
    TRUST_PROXY: z.coerce.number().int().min(0),
    APP_DEBUG: bool,
    APP_TIMEZONE: z.string().min(1),
    APP_LOCALE: z.string().min(1),
    // Logging & Observability
    LOG_LEVEL: z.enum(['trace', 'debug', 'info', 'warn', 'error', 'fatal']),
    LOG_FORMAT: z.enum(['pretty', 'json']),
    // Database
    DB_CONNECTION: z.enum(['postgres', 'mysql', 'sqlite', 'azure-postgres', 'azure-mysql']),
    DB_DATABASE: z.string().min(1),
    // HTTP / API
    API_PREFIX: z.string().min(1),
    API_VERSION: z.string().min(1),
    API_DOCS: bool,
    CORS_ORIGINS: list,
    RATE_LIMIT: z.string().regex(/^\d+\/(s|min|h|day)$/, 'use a rate like 120/min'),
    // UI
    VITE_APP_NAME: z.string().min(1),
    VITE_API_URL: z.string().min(1),
  })
  .superRefine((env, ctx) => {
    if (env.APP_ENV !== 'local' && env.APP_DEBUG) {
      ctx.addIssue({
        code: 'custom',
        path: ['APP_DEBUG'],
        message: 'APP_DEBUG may only be true when APP_ENV=local (it would expose error details)',
      })
    }
    // config/cors.ts allows credentials (cookies), so a wildcard origin is never safe.
    if (env.CORS_ORIGINS.some((origin) => origin.includes('*'))) {
      ctx.addIssue({
        code: 'custom',
        path: ['CORS_ORIGINS'],
        message: 'CORS_ORIGINS cannot contain * while credentials are allowed: list each origin',
      })
    }
    const insecure = env.CORS_ORIGINS.some((origin) => !origin.startsWith('https://'))
    if (env.APP_ENV === 'production' && insecure) {
      ctx.addIssue({
        code: 'custom',
        path: ['CORS_ORIGINS'],
        message: 'every CORS_ORIGINS entry must start with https:// in production',
      })
    }
  })

/** The validated environment type. */
export type Env = z.infer<typeof envSchema>

/**
 * Guards the environment contract: a complete .env is accepted and a broken one is refused.
 * Keep it passing when you add variables (add them to `valid` below).
 */
import { describe, expect, test } from 'vitest'
import { envSchema } from '../../env.schema.ts'

const valid = {
  APP_NAME: 'kiosk',
  APP_ENV: 'local',
  APP_KEY: 'not-a-real-secret-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx',
  APP_URL: 'http://localhost:3000',
  APP_PORT: '3000',
  TRUST_PROXY: '0',
  APP_DEBUG: 'true',
  APP_TIMEZONE: 'UTC',
  APP_LOCALE: 'en',
  LOG_LEVEL: 'info',
  LOG_FORMAT: 'pretty',
  DB_CONNECTION: 'sqlite',
  DB_DATABASE: 'storage/database.sqlite',
  API_PREFIX: '/api',
  API_VERSION: 'v1',
  API_DOCS: 'true',
  CORS_ORIGINS: 'http://localhost:3000',
  RATE_LIMIT: '120/min',
  VITE_APP_NAME: 'kiosk',
  VITE_API_URL: '/api/v1',
}

describe('environment', () => {
  test('accepts a complete environment', () => {
    expect(envSchema.safeParse(valid).success).toBe(true)
  })

  test('refuses a missing required key', () => {
    const { APP_NAME: _removed, ...incomplete } = valid
    expect(envSchema.safeParse(incomplete).success).toBe(false)
  })

  test.each(['test', 'staging', 'production'])('refuses debug mode when APP_ENV=%s', (APP_ENV) => {
    expect(envSchema.safeParse({ ...valid, APP_ENV, APP_DEBUG: 'true' }).success).toBe(false)
  })

  test.each(['*', 'https://*.example.com'])('refuses the CORS origin %s', (CORS_ORIGINS) => {
    expect(envSchema.safeParse({ ...valid, CORS_ORIGINS }).success).toBe(false)
  })

  test('requires https:// CORS origins in production', () => {
    const production = { ...valid, APP_ENV: 'production', APP_DEBUG: 'false' }
    const plain = { ...production, CORS_ORIGINS: 'http://app.example.com' }
    const secure = { ...production, CORS_ORIGINS: 'https://app.example.com' }
    expect(envSchema.safeParse(plain).success).toBe(false)
    expect(envSchema.safeParse(secure).success).toBe(true)
  })
})

/**
 * The whole UI: <StrutvaneApp> reads the API manifest and renders a menu of every resource the
 * user may see, with list, create, detail and edit pages for each and no code per model. Add

import { StrutvaneApp } from '@strutvane/ui/react'

export function App() {
  return (
    <StrutvaneApp
      apiUrl={import.meta.env.VITE_API_URL}
      appName={import.meta.env.VITE_APP_NAME}
      routes={routes}
      auth={false}
    />
  )
}

===== web/pages/README.md =====
# Pages

Every resource already has its pages, built from the API manifest: list (`/invoices`), create
(`/invoices/new`), detail (`/invoices/:id`) and edit (`/invoices/:id/edit`).

Put your own screens here and register them in `web/router.tsx`:

```tsx
{ path: '/reports', title: 'Reports', element: <Reports /> }
```

Routes with a `title` appear in the menu. A route wins over the built-in page at the same path,
so `/invoices` replaces the invoice list. To change single fields, columns or messages instead,
pass `overrides` (`widgets`, `fieldCells`, `messages`) to `<StrutvaneApp>` in `web/app.tsx`.
